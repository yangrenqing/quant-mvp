# cc quant-mvp autopilot

> 目标：让 cc 在不反复等待杨大师点头的情况下，持续推进 `quant-mvp` 的内部优化。

## 1. 默认推进范围

在以下范围内，cc 可以默认自行推进：
- 仓内代码优化
- 审计与可信度提升
- 回测/数据/策略比较/进化门槛改进
- 补文档、补报告、补测试、补脚本
- 清理 backlog、补状态文件、做阶段性收口

## 2. 默认不自动推进的事项

遇到以下情况要先确认：
- 破坏性操作
- 对外发送或联网发布
- 明显改变策略方向或口径
- 可能明显影响既有使用习惯
- 涉及资金/交易执行权限的实际外部动作

## 3. 自运行循环

每次续跑时按这个顺序：
1. 读 `docs/sprint_72h_plan.md`
2. 读 `reports/sprint72_status.json`
3. 读 `reports/sprint72_backlog.md`
4. 看 `git status`
5. 选择一个当前最高杠杆的小阶段任务
6. 留下工件（报告 / 状态 / 文档 / 代码 / 测试）
7. 更新状态文件
8. 必要时提交 git

## 4. 当前优先方向

优先级顺序：
1. data trustworthiness
2. backtest trustworthiness
3. strategy comparison clarity
4. controlled evolution quality
5. automation hardening

## 5. 运行原则

- 优先小步快跑
- 优先留下可恢复工件
- 优先把结论写进文件，而不是只留在聊天里
- 优先做高杠杆项，不做功能漫灌
- 长任务要会自我收口，便于下次续跑

## 6. 快报规则

- 启动新一轮阶段工作时，可简短报备一次
- 中间无关键变化时不频繁打扰
- 遇到阻塞、风险、需要决策时立刻汇报
- 每完成一个像样阶段，就给一条快报

## 7. 成功定义

只要没有触发停手边界，cc 就应持续把 `quant-mvp` 往这几个方向推：
- 更可信
- 更可解释
- 更可比较
- 更可进化
- 更可恢复
